This is the first post. It exists mostly to prove the machinery works — but it
also doubles as a reference for how to write the next one.

## Writing a post

Every post is one Markdown file in the `_posts/` directory, named
`YYYY-MM-DD-a-short-slug.md`. The date in the filename sets the publication
date and the URL; the slug becomes the last part of the path.

The block at the top — between the `---` fences — is *front matter*, and it
controls how the post is presented:

```yaml
---
title: "The title, as it appears everywhere"
subtitle: "Optional. Shows under the title and in post lists."
date: 2026-09-04 09:00:00 +0000
tags: [writing, notes]
---
```

Everything after that is just Markdown. Headings, **bold**, *italics*,
[links](https://example.com), lists, and code all work the way you'd expect.

> Block quotes look like this — useful for pulling out a line worth
> lingering on.

## Publishing

Commit the file, push it to the `master` branch, and GitHub Pages rebuilds the
site automatically. There's no separate deploy step and nothing to run locally
unless you want a preview first.

To draft something without publishing it, put the file in a `_drafts/`
directory instead — it stays invisible to the live site until you move it into
`_posts/` and give it a date.
